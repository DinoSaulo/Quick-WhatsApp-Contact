# Fix Rocky Linux 9 Package Conflict in CI Pipeline

## Problem
The GitHub Actions workflow job "4 · Instalacao · Chrome 151 - Rocky Linux" is failing with a package conflict error:

```
Problem: problem with installed package curl-minimal-7.76.1-26.el9_3.2.0.1.x86_64
  - package curl-minimal-7.76.1-26.el9_3.2.0.1.x86_64 from @System conflicts with curl provided by curl-7.76.1-40.el9.x86_64 from baseos
```

**Location:** `.github/workflows/ci.yml` lines 246-251

## Root Cause
The DNF package manager in Rocky Linux 9 has a pre-installed `curl-minimal` package that conflicts with the full `curl` package. The current setup command tries to install `curl` without resolving this conflict.

## Solution
Add the `--allowerasing` flag to the DNF install command for Rocky Linux. This flag automatically replaces conflicting packages instead of aborting the installation.

## Files to Modify
- **`.github/workflows/ci.yml`** - Update the Rocky Linux installation setup command

## Specific Change Required
In the `installation-test` job matrix entry for "Chrome 151 - Rocky Linux":

**Before:**
```yaml
setup: >-
  dnf install -y https://dl.fedoraproject.org/pub/epel/epel-release-latest-9.noarch.rpm &&
  dnf install -y --setopt=install_weak_deps=False git curl nodejs npm chromium
```

**After:**
```yaml
setup: >-
  dnf install -y https://dl.fedoraproject.org/pub/epel/epel-release-latest-9.noarch.rpm &&
  dnf install -y --allowerasing --setopt=install_weak_deps=False git curl nodejs npm chromium
```

## What This Does
- `--allowerasing` tells DNF to replace `curl-minimal` with the full `curl` package
- Maintains all other install parameters (`--setopt=install_weak_deps=False` for minimal dependencies)
- Allows the Rocky Linux 9 container to complete system setup successfully

## Testing
After applying this fix, the workflow should pass all stages for the Rocky Linux 9 installation test.
